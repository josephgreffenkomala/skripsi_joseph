03 / Mesin di dalam program

Anatomi Qwen3-0.6B

Qwen ini adalah Transformer decoder-only yang dense. “Decoder-only” berarti jaringan dipakai untuk memprediksi kelanjutan urutan. “Dense” berarti setiap token melewati seluruh 28 blok, tanpa pemilihan pakar seperti pada Mixture of Experts.

“Causal” berarti posisi token hanya boleh memakai informasi dari posisi itu sendiri dan posisi sebelumnya. Saat menghasilkan jawaban, model belum mempunyai token masa depan.

Embedding: dari nomor menjadi representasi

ID token hanyalah indeks, seperti nomor halaman. Besar ID tidak menyatakan besar maknanya. Embedding mengambil satu baris dari tabel bobot dan menghasilkan 1.024 angka untuk token itu.

ID token → tabel embedding [151936, 1024] → vektor [1024]

Angka-angka ini dipelajari selama training. Tidak ada aturan bahwa “angka pertama berarti hewan” atau “angka kedua berarti tempat”. Pola makna tersebar dalam banyak dimensi.

Setelah melalui attention, representasi token juga bergantung pada konteksnya. Token yang sama dalam dua kalimat bisa memiliki representasi akhir berbeda.

28
blok pengolahan

Jangan membayangkan blok 1 khusus tata bahasa dan blok 28 khusus logika. Kita mengetahui struktur matematisnya, bukan pembagian pekerjaan manusia yang pasti.

1.024
angka per posisi token

Ukuran ini dipertahankan pada jalur utama, supaya hasil attention dan MLP dapat dijumlahkan dengan residual.

LM head: dari representasi menjadi kandidat

Setelah blok terakhir, LM head menghitung satu skor (logit) untuk setiap slot token. Saat memilih kelanjutan, kita memakai skor dari posisi terakhir. Skor kemudian diproses menjadi distribusi peluang untuk sampling.

Konfigurasi mengaktifkan tie_word_embeddings=true: bobot embedding masukan dibagi pakai dengan bobot LM head. Operasinya berbeda—masukan mengambil baris berdasarkan ID, keluaran menghitung skor terhadap tabel tersebut.

0.6B adalah ukuran nominal parameter, bukan jumlah lapisan atau ukuran file. Model mempunyai jutaan angka di embedding, proyeksi attention, MLP, dan normalisasi. Ukuran file serta RAM juga dipengaruhi format angka dan cara bobot disimpan/dimuat.
04 / Menghubungkan token

Membongkar attention

Attention mencampur informasi antarposisi. Misalnya, untuk memproses “ia” dalam kalimat “Budi membawa buku karena ia ingin membaca”, model dapat menggunakan informasi token sebelumnya. Contoh ini menjelaskan mekanisme, bukan hasil pengukuran attention Qwen.

Tiga proyeksi

Query: fitur apa yang sedang dicari posisi ini?

Key: fitur apa yang bisa dicocokkan pada posisi lain?

Value: informasi apa yang akan digabungkan?

Empat langkah

  1. Buat Q, K, dan V dari representasi.
  2. Hitung kecocokan Q dengan K.
  3. Mask posisi masa depan; ubah skor menjadi bobot.
  4. Gabungkan V menurut bobot itu.
Lebih teknis: rumus attention
Attention(Q, K, V) = softmax(QKᵀ / √128 + mask) V

QKᵀ menghitung kecocokan antarposisi. Pembagian dengan √128 mengatur skala karena dimensi tiap head adalah 128. Softmax membuat bobot nonnegatif yang totalnya 1. Posisi terlarang mendapat mask negatif tak hingga sebelum softmax, sehingga bobotnya 0.

Pada Qwen ini, Q dan K dinormalisasi per head, kemudian diberi transformasi posisi RoPE sebelum perhitungan kecocokan. Bentuk rumus di atas memakai Q dan K yang sudah diproses itu.

Causal mask: token tidak melihat masa depan

Ilustrasi berikut memakai empat posisi token buatan, bukan tokenisasi Qwen yang sebenarnya. Baris adalah posisi yang sedang memproses; kolom adalah posisi yang boleh dibaca.

Posisi ↓ / dibaca →1: Saya2: suka3: belajar4: AI
1: SayaBolehDiblokirDiblokirDiblokir
2: sukaBolehBolehDiblokirDiblokir
3: belajarBolehBolehBolehDiblokir
4: AIBolehBolehBolehBoleh

GQA: 16 Query head berbagi 8 pasangan K/V

Head adalah cabang perhitungan attention. GQA (Grouped Query Attention) mengelompokkan dua Query head untuk berbagi satu pasangan Key/Value head.

Manfaatnya: jumlah data K/V yang disimpan lebih kecil daripada memakai 16 head K/V dengan dimensi sama. Ini membantu menghemat KV cache selama generasi.

Lebih teknis: dimensi aktual Qwen ini
Operasi per tokenDimensi
Masukan1024
Proyeksi Q1024 → 2048 = 16 × 128
Proyeksi K dan V, masing-masing1024 → 1024 = 8 × 128
Gabungan 16 hasil attention2048
Proyeksi output2048 → 1024

Perhatikan: dimensi head di konfigurasi adalah 128. Jangan menghitungnya dengan 1024 ÷ 16 = 64; model ini menetapkan head_dim secara eksplisit.

RoPE: urutan juga membawa informasi

“Kucing mengejar tikus” berbeda dari “tikus mengejar kucing”. RoPE (Rotary Position Embedding) memutar pasangan komponen Q dan K menurut posisi token. Perbandingan Q dan K kemudian dapat membawa informasi jarak relatif antartoken.

RoPE tidak menambahkan kata baru dan tidak mengubah ID token. Ia bekerja pada angka di dalam attention. Konfigurasi lokal menggunakan rope_theta=1000000.

05 / Mengolah hasil perhatian

MLP, normalisasi, dan jalur residual

Attention menggabungkan informasi antarposisi. Sesudahnya, MLP mengolah fitur di setiap posisi secara terpisah, dengan bobot yang sama untuk semua posisi dalam satu blok. Masukannya sudah membawa konteks dari attention.

SiLU adalah fungsi nonlinier: keluaran tidak sekadar kelipatan lurus masukan. Gerbangnya memberi cara yang dipelajari untuk mengatur fitur yang diteruskan. Ini berbeda dari router pemilih expert pada MoE.

Mengapa masih ditambah dengan masukan awal?

Residual adalah jalur pintas. Alih-alih mengganti representasi seluruhnya, sebuah subbagian menambahkan perubahan terhadap representasi yang sudah ada.

h = x + Attention(RMSNorm(x))
keluaran = h + MLP(RMSNorm(h))

Penjumlahan dapat dilakukan karena bentuk tensor cocok. Jalur ini juga membantu aliran gradien saat model dilatih. Dalam eksperimen kita, bobot sudah tersedia; kita hanya menjalankan perhitungan ke depan.

RMSNorm mengatur skala vektor berdasarkan akar rata-rata kuadrat elemennya, lalu memakai faktor skala yang dipelajari. Ia membantu kestabilan angka. RMSNorm tidak sama dengan mengubah semua angka menjadi peluang.

28 blok ≠ 28 token jawaban. Setiap langkah generasi memanfaatkan seluruh tumpukan blok. Jumlah token jawaban ditentukan proses generate, penanda berhenti, dan batas token.
06 / Satu token setiap langkah

Cara jawaban terbentuk

Model menghitung kandidat token berikutnya. Setelah satu token dipilih, token itu menjadi bagian konteks untuk memprediksi token selanjutnya. Proses berulang ini disebut autoregresif.

Ikuti satu langkah generasi

Simulasi alur dengan urutan tetap. Potongan berikut bukan hasil tokenizer atau inference Qwen.

Prompt: “Berapa hasil 2 + 2?”

Belum ada token jawaban.

Langkah 0: prompt diproses terlebih dahulu (prefill).

Prefill dan decode

Prefill memproses token prompt dan menyiapkan K/V pada setiap blok. Banyak posisi prompt bisa dihitung bersama, dengan causal mask. Decode kemudian menghasilkan kelanjutan satu langkah demi satu langkah.

Dengan KV cache, K/V token lama disimpan di memori, sehingga tidak perlu dihitung ulang semuanya. Token baru tetap membaca informasi sebelumnya melalui attention. Cache ini sementara dan membesar saat konteks bertambah.

Jenis cacheTempat & isiGunanya
Cache Hugging FaceDisk: bobot, konfigurasi, tokenizerMenghindari unduh ulang, bisa lintas eksekusi
KV cacheMemori saat inference: Key dan Value tiap blokMenghindari hitung ulang K/V token lama

Sampling: skor bukan jawaban final

Script memakai do_sample=True, temperature=0.7, top_k=20, dan top_p=0.8. Token tidak selalu dipilih dari skor paling tinggi saja.

  • Temperature: mengubah ketajaman distribusi. Nilai lebih rendah biasanya memusatkan peluang pada kandidat kuat.
  • Top-k: mempertahankan sejumlah kandidat dengan skor tertinggi.
  • Top-p: mempertahankan kumpulan kandidat berpeluang tinggi hingga mencapai ambang peluang kumulatif. Kombinasi filter mengikuti implementasi library.

Coba pengaruh temperature

Distribusi ilustratif dari logits buatan [3, 2, 1]. Tidak memakai top-k/top-p dan tidak mengukur keluaran model.

Peluang lebih menyebar berarti lebih banyak kandidat mungkin dipilih; itu tidak otomatis membuat jawaban lebih benar.

Kapan berhenti?

Generasi berhenti saat model menghasilkan token akhir yang dikonfigurasi atau mencapai max_new_tokens. Default script 128; argumen menerima 1–1024. Pertanyaan dibatasi 2048 token setelah chat template diterapkan.

Batas latihan ini sengaja lebih kecil daripada kemampuan konteks yang disebut model card. Model card menyebut 32.768 token; konfigurasi lokal memiliki max_position_embeddings=40960. Nilai konfigurasi tersebut bukan bukti kualitas teruji sampai panjang itu.

Mode enable_thinking=False mengatur format permintaan jawaban langsung. Mode thinking tidak menghapus atau menambah blok Transformer. Seed 42 membantu pengulangan, tetapi hasil tidak dijamin identik lintas perangkat dan versi.

Kenapa ada dua macam mask?

attention_mask dari tokenizer menunjukkan token input yang valid dan padding bila ada. Causal mask membatasi pembacaan posisi masa depan. Keduanya berkaitan dengan attention, tetapi tujuannya berbeda.

Memahami bentuk data

input_ids:        [1, T]              # ID token prompt
setelah embedding:[1, T, 1024]        # representasi token
generated:        [1, T + N]          # prompt + jawaban
answer_ids:       [N]                # hanya jawaban

T adalah panjang input, N jumlah token baru. Saat menggunakan KV cache pada langkah decode, model terutama memproses token baru dengan data K/V lama yang tersedia.

Contoh pemotongan keluaran

generated = [token_input_1, token_input_2, token_jawaban_1, token_jawaban_2]
input_length = 2
answer_ids = generated[2:]  # dua token jawaban saja

Ini contoh daftar sederhana untuk menjelaskan slicing. Di program sebenarnya, generated adalah tensor dua dimensi sehingga indeks pertamanya adalah 0.

08 / Coba jelaskan kembali

Cek pemahamanmu

Pilih jawaban, lalu baca alasannya. Kamu tidak harus menjawab benar pada percobaan pertama.

1. Apa yang berubah saat inference?

Saat inference, konteks bertambah ketika token dipilih. Bobot model tetap; pembaruan bobot dilakukan dalam training.

2. Mengapa memakai GQA?

GQA berbagi K/V antar-Query head. Pada model ini seluruh 28 blok tetap digunakan.

3. Cache mana yang dipakai untuk offline?

File cache menyimpan unduhan lintas eksekusi. KV cache membantu penghitungan selama proses generasi.

Latihan terminal

  1. Jalankan pertanyaan yang sama dengan batas 16 dan 128 token.
  2. Coba mode offline setelah unduhan selesai.
  3. Temukan baris kode untuk loading, tokenisasi, generate, dan decode.
  4. Tanpa melihat diagram, ceritakan perjalanan satu token melalui embedding, attention, MLP, dan LM head.
Tanda sudah memahami: kamu bisa menjelaskan mengapa 28 blok bukan 28 token, mengapa model perlu tokenizer, dan mengapa menjalankan prompt baru tidak melatih ulang bobot. Kalau satu langkah belum jelas, tanyakan bagian itu—misalnya “jelaskan Q dan K dengan angka kecil”.

1. Model apa yang dipakai?

Qwen/Qwen3-0.6B, model percakapan resmi Qwen dengan ukuran nominal sekitar 600 juta parameter. Berdasarkan pengecekan katalog resmi pada 25 September 2026, ini pilihan terbaru yang ditemukan untuk percakapan umum dengan ukuran tepat 0.6B. Varian 0.6B untuk suara, embedding, reranking, atau moderasi memiliki tugas berbeda. Qwen3.5 punya varian kecil 0.8B; itu tidak memenuhi permintaan ukuran 0.6B.

Sumber: model card Qwen3-0.6B, katalog resmi Qwen, Qwen3.5-0.8B.

Versi library di requirements.txt sengaja ditetapkan agar contoh stabil; versi library berbeda dari versi model. Model diambil dari revisi main yang tersedia ketika dijalankan online, sehingga revisi bobot belum dikunci untuk penelitian.

Python 3.12 dipakai untuk kecocokan dengan versi library contoh. Instalasi pertama memilih PyTorch CPU supaya tidak mengunduh paket CUDA yang besar. Script memang menggunakan CPU meskipun dijalankan di komputer yang memiliki GPU.

Pemakaian pertama perlu internet untuk mengunduh model; bobot yang terunduh sekitar 1,5 GB di disk, ditambah tokenizer, library, dan cache instalasi. Sediakan beberapa GB ruang kosong. Script memakai float32 pada CPU: bobot di RAM membutuhkan kira-kira 3 GB, ditambah memori untuk perhitungan dan proses pemuatan. Itu perkiraan, bukan batas maksimum. Jika RAM hampir penuh, tutup aplikasi berat terlebih dahulu. CPU bisa memerlukan waktu cukup lama untuk menyelesaikan jawaban.

Ganti pertanyaan:

python load_qwen.py --prompt "Apa bedanya RAM dan penyimpanan? Jawab singkat."

Berikan ruang lebih panjang untuk jawaban:

python load_qwen.py --prompt "Jelaskan token dengan contoh sederhana." --max-new-tokens 256

Sesudah unduhan lengkap, coba tanpa mengambil file dari internet:

python load_qwen.py --offline --prompt "Berapa hasil 2 + 2?"

--offline memakai cache yang sudah ada. Setiap menjalankan script, model tetap dibaca lagi ke RAM. Cache menghemat unduhan, bukan mempertahankan model di RAM. Keluar dari lingkungan Python dengan deactivate.

5. Apa yang terjadi dari awal sampai muncul jawaban?

Pertanyaanmu
    ↓
Chat template: susun pesan ke format percakapan Qwen
    ↓
Tokenizer: ubah teks menjadi deretan angka
    ↓
Model: hitung peluang token berikutnya
    ↓
Generate: pilih token, lalu ulangi hingga selesai atau mencapai batas
    ↓
Decode: ubah token jawaban menjadi teks yang bisa dibaca

Model tidak mengambil jawaban dari Google. Script ini melakukan perhitungan lokal menggunakan bobot model. Jawaban dapat salah, terutama pada model kecil.

6. Membaca kode secara bertahap

Mulai dari main(), yaitu fungsi yang mengatur urutan kerja program.

  1. argparse membaca opsi terminal seperti --prompt. Tanpa opsi, program memakai pertanyaan contoh. Input kosong dan batas token di luar 1–1024 ditolak.
  2. MODEL_ID menunjuk repositori model di Hugging Face, tempat distribusi model.
  3. AutoTokenizer.from_pretrained(...) mengambil aturan pemecahan teks.
  4. AutoModelForCausalLM.from_pretrained(...) memuat model yang sudah dilatih. CausalLM di sini berarti model memprediksi token berikutnya dari token sebelumnya.
  5. model.eval() mengatur perilaku model untuk evaluasi/inference.
  6. messages berisi satu pesan dengan peran user. Ini format data percakapan.
  7. apply_chat_template(...) menambahkan penanda percakapan yang dikenali model. enable_thinking=False dipilih untuk latihan jawaban langsung. Kita belum menambahkan mode thinking agar contoh awal tetap sederhana.
  8. return_tensors="pt" meminta keluaran tokenizer berupa tensor PyTorch.
  9. torch.inference_mode() menonaktifkan pencatatan gradien yang dipakai saat training.
  10. model.generate(...) menghasilkan token baru. max_new_tokens membatasi jumlah token tambahan, bukan jumlah kata atau panjang input.
  11. generated[0, input_length:] mengambil hasil pertama, lalu membuang bagian input. Tanpa langkah ini, pertanyaan ikut tercetak sebagai jawaban.
  12. tokenizer.decode(...) mengubah token baru kembali menjadi teks.

Pengaturan sampling memilih dari beberapa kemungkinan token: temperature mengatur ketajaman distribusi peluang, sedangkan top_p dan top_k membatasi kandidat. Untuk awal, biarkan nilainya tetap. Seed 42 membantu mengulang percobaan, tetapi bukan jaminan hasil identik di semua perangkat dan versi library.

if __name__ == "__main__": memastikan main() dijalankan ketika file ini dipanggil sebagai program. Import library berat diletakkan setelah pembacaan opsi agar python load_qwen.py --help tetap bisa dipakai sebelum library terpasang.

7. Latihan kecil agar benar-benar paham

Lakukan satu per satu; jangan mengubah semuanya sekaligus.

  1. Jalankan pertanyaan bawaan. Temukan baris nama model, perangkat, dan jumlah token.
  2. Ubah hanya --prompt. Perhatikan bahwa script-nya sama, tetapi input berbeda.
  3. Minta penjelasan panjang dengan batas 16 token, kemudian 128 token. Perhatikan kemungkinan jawaban terpotong. Batas token yang lebih besar bukan jaminan jawaban lebih benar.
  4. Jalankan dengan --offline sesudah unduhan selesai. Ini menunjukkan peran cache.
  5. Jelaskan dengan bahasamu sendiri alur: teks → token → model → token → teks.

Cek pemahaman:

  • Mengapa 0.6B bukan 0,6 GB? Karena B menghitung parameter, sedangkan GB menghitung byte.
  • Apakah prompt baru mengubah bobot? Tidak; script hanya melakukan inference.
  • Mengapa perlu tokenizer? Perhitungan model memakai ID token, bukan huruf mentah.
  • Mengapa pertanyaan dipotong dari generated? Hasil generate juga memuat input awal.
  • Apakah program ini chatbot dengan ingatan? Belum; satu eksekusi hanya satu pertanyaan.

8. Jika terjadi kendala

Gejala Langkah pertama
ModuleNotFoundError Aktifkan .venv dan jalankan instalasi requirements.
KeyError: 'qwen3' Pastikan memakai Transformers dari requirements, bukan instalasi global lama.
Unduhan gagal Periksa internet lalu jalankan ulang; unduhan menggunakan cache.
Mode offline gagal Jalankan online terlebih dahulu sampai semua file berhasil dimuat.
Program berhenti dengan Killed Periksa RAM; tutup aplikasi berat dan coba prompt pendek.
Jawaban lama muncul Periksa proses pemuatan/unduhan; CPU menghasilkan token bertahap, script mencetak setelah selesai.
Jawaban terpotong Naikkan --max-new-tokens, misalnya ke 256.
Jawaban keliru Coba instruksi lebih sederhana dan periksa faktanya; keberhasilan program tidak berarti jawabannya benar.

Untuk mempelajari API lebih lanjut: panduan chat template Transformers dan dokumentasi inference_mode PyTorch.
